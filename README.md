# arb-cockpit

개인용 **반자동 아비트라지 콕핏**. 여러 종류의 차익거래 기회를 하나의 랭킹 보드로 모아 실시간 감시하고, 고른 기회를 **원클릭(반자동)으로 실행**한다. 코인 감시 터미널(coin-tracker)의 실행 담당 짝으로, 별개의 Next.js 앱이다.

- **포트 `:3100`** — coin-tracker(:3000)와 안 겹침
- 단일 사용자 · 인증 없음 · 한글 UI · 리퀴드 글래스 디자인(다크/라이트)
- **실행 타깃 = 한국 로컬 서버** — 업비트/빗썸 API·WS·공지가 네이티브로 되고(비KR IP는 403), 거래소·체인과 지연이 짧다

> ⚠️ **DRY-RUN이 기본.** 실주문·실전송은 키를 넣고 `DRY_RUN=false`로 바꿔야만 나간다.
> 자금 이동 키(개인지갑 · `EXEC_TOKEN`)는 절대 커밋 금지 — `.gitignore`가 `.env*`와 `data/`를 덮는다.

## 전략

| 종류 | 상태 | 내용 |
|------|------|------|
| **kimchi** (김프) | ✅ 실배선 | 업비트/빗썸 KRW vs 바낸/바이빗/OKX USDT 프리미엄. 실시간 USDT/KRW(테더 프리미엄) 환산, 코인별 출금비·헷지비·자동 보정 반영, 입출금 게이트로 실행 가부 판정 |
| **cross-cex** (거래소간) | ✅ 실배선 | 해외 CEX 간 현물 가격차. 전송형(싼 곳 매수 → 출금 → 비싼 곳 매도). 바이비트/OKX 입출금 게이트·입금확인·출금 tx 조회 배선 |
| **cex-dex** | ✅ 전송형 배선 | OKX DEX 애그리게이터 실행가능 견적 vs 바낸 톱오브북. 온체인 컨트랙트 검증 + 입출금 체인 일치 게이트 |
| **funding-basis** (펀딩) | 👁 감시 | 거래소 간 펀딩비 차이(캐시앤캐리). 감쇠 모델·APR 표기. 실행 미배선(perp-DEX 주문 라우팅 필요) |

`USE_MOCK`(기본 켜짐)은 **라이브 데이터가 없는 전략의 빈자리만** 데모 기회로 채운다 — 실측 행과 가짜 행이 섞이지 않는다.

## 탭 구성 (`app/page.tsx`)

- **대시보드** — 라이브 전환 체크리스트, 리스크 여유 게이지, KPI, 자금 배분
- **갭** — 실시간 갭 보드 + 갭 검사창(양다리 차트·비용 분해·전송)
- **펀딩** — 펀딩비 차익(감시)
- **상장** — 상장따리: 신규 상장 감지·상세·DEX 원클릭 매수·핫월렛 물량
- **운영** — 진행 중 실행·거래 기록·손익 시각화·게이트·킬 스위치
- **자산** — 잔고·브릿지·지갑 tx 히스토리

## 상장따리 (`lib/listings.ts`)

신규 상장을 자동 감지(공지 파싱 + 마켓 diff + 텔레그램 채널)하고 상세를 풀스크린으로 연다. **공지 감지가 이 제품의 모트**라 반응 경로에 대기를 두지 않는다 — 등록·알림·자동매수를 먼저 보내고 개장시각은 나중에 패치하며, 해외 거래소 탐색은 3곳을 동시에 띄우고 우선순위대로 먼저 온 것을 쓴다.

- **신호 스트립** — 가격·시총·24h 볼륨·김프·즉시유입/24h·24h 피크
- **차트** — TradingView(CEX 5종) + DexScreener + 네이티브 캔들
- **통합 매수·매도 표** — CEX + DEX 한 표. DEX 행엔 스왑 미리보기(예상/최소 수령·슬리피지·가격 임팩트·가스·라우팅 + 허니팟·전송세 경고)와 유동성 등급
- **거래소 핫월렛 잔고** — 거래소별 핫/콜드 물량 + 핫 유입 Δ/분(덤프 경계)
- **자동매수** — 이중 옵트인(`armed` + `LISTING_AUTO_LIVE=true`) + fail-closed 가드(CG 미등록/저시총/기펌핑 스킵) + 동시 등록 차단

## 온체인 (OKX Web3 / OnchainOS, `lib/dex.ts`)

OKX DEX API **V6**로 견적·스왑·전송 빌드·조회를 한다. **서명·방송은 항상 로컬**(ethers / solana web3) — 프라이빗 키는 서버 파일에만.

- **28체인** 지갑 잔고·tx 조회, **21체인** DEX 스왑
- 전송 tx 빌드(`sign-info`: 가스·논스) → 로컬 서명 → 로컬 RPC 방송
- 스왑 서명은 OKX가 반환한 라우터 주소로만(화이트리스트)
- **브로드캐스트된 tx의 해시를 잃지 않는다** — 방송 후 컨펌 확인이 실패해도 해시를 반환해 "보냈지만 미확인"과 "안 나감"을 구분한다(재시도 이중 전송 방지의 핵심)

## 실행 엔진 (`lib/runEngine.ts`)

실행 상태머신을 **서버 모듈**이 소유한다 — 시작하면 브라우저 탭을 닫아도 완주한다. UI(`lib/runStore.ts`)는 `/api/runs`를 폴링하는 미러.

단계(김프 개인지갑 홉 기준):

```
매수 → [헷지 숏] → 출금 → 지갑 수신 확인 → 지갑→거래소 송금 → 입금 확인 → 매도 → [헷지 청산] → 정산
```

- **비가역 경계는 플랜의 `irreversible` 플래그에서 유도한다.** 단계 이름(`withdraw`)으로 찾지 않는다 — 그 방식은 `withdraw`가 없는 플랜(cex-dex buyDex)에서 롤백·확인정지가 통째로 새는 구멍이 있었다
- 자동화 레벨: 전수동 / 비가역 단계 전 정지(권장) / 매도 전 정지 / 전자동
- 비가역 단계 직전 **엣지 재검증**(미반영 비용까지 포함해 비교), 그 이전 실패는 **진입 롤백**(롤백도 슬리피지 가드 → 초과 시 보류 + 텔레그램)
- **멱등성** — 성공한 단계는 재시도해도 재전송하지 않는다. "실패했지만 성공했을 수 있는"(전송 후 오류) 결과는 `ambiguous`로 표시해 자동 재시도·롤백을 모두 차단하고 사람을 부른다
- **대기와 실패를 구분** — 입금·지갑 수신 미도착은 실패가 아니라 `pending`이며 20초마다 자동 재확인(상한 90분). 서킷 브레이커는 실집행 실패만 센다
- 런 스냅샷 즉시 persist — 재시작 시 중단 런을 경고와 함께 복원(자동 재개 안 함)

## 리스크·안전장치

- **`DRY_RUN=true`(기본)** — 실행은 `DRY_RUN=false` + 해당 키가 있어야만. 전환은 의도적으로 설정창에서 제외(`.env.local` + 재시작만)
- **루프백 전용 바인딩** — dev·프로덕션·pm2 모두 `-H 127.0.0.1`. 이 앱에는 로그인이 없으므로 그게 유일한 경계다. LAN에 여는 `*:lan` 스크립트가 따로 있지만 권장하지 않는다
- **출처 확인(`middleware.ts`)** — 상태를 바꾸는 `/api` 요청은 Origin이 이 서버 자신일 때만 받는다. 루프백 바인딩이 못 막는 호출자가 하나 있기 때문이다: **당신의 브라우저**. 웹서핑 중 아무 페이지나 `fetch("http://localhost:3100/api/risk", {method:"POST"})`를 쏠 수 있고(응답은 못 읽어도 부수효과는 일어난다), 브라우저는 이미 localhost 안이라 바인딩과 무관하다. Origin이 아예 없는 요청(curl·크론 헬스체크·pm2)은 통과 — 브라우저는 교차 출처에서 Origin을 생략할 수 없으므로 이 예외로 새지 않는다. Host가 공인 도메인이면 거부(DNS 리바인딩)
- **라이브 실행 인증** — 돈이 실제로 나가는 액션은 `EXEC_TOKEN`(x-exec-token). 킬 스위치·취소는 무인증(비상 정지를 인증으로 막지 않음)
- **킬 스위치는 영속된다** — 재시작으로 풀리지 않는다(해제는 명시적 조작)
- **일손실 한도는 KST 자정 기준**이며 정산뿐 아니라 **청산 손익도 반영**한다
- 노출 한도는 미정리 포지션(오류로 끝났지만 물량·헷지가 남은 런)도 센다
- 라이브에서 **불확실하면 실패**한다 — 체인 미상·주소 미확인·토큰 미확인·태그 필수 코인의 태그 없음·키 없음·미배선은 전부 하드 실패
- 체결량을 확인 못 한 매수·헷지는 명목 수량으로 진행하지 않고 중단
- 슬리피지 상한(진입·롤백·청산 모두), 최소 출금 수량 게이트, 헷지 증거금 워치
- 크래시 훅(uncaughtException → 알림 후 종료, pm2가 깨끗하게 재기동)
- **`/api/health`는 진단이자 복구 훅** — 스캔 스냅샷이 낡았거나 갱신 래치가 걸리면 새 스캔을 띄운다. 프로세스가 죽지 않고 멈추는 고장은 pm2가 못 잡으므로 1분 크론 권장(`RUNBOOK.md`)

## 실행

```bash
npm install
cp .env.example .env.local     # 키 채우기 (없어도 DRY-RUN/데모로 돎)
npm run dev                    # http://localhost:3100
npm run typecheck              # tsc --noEmit
```

상시 운용은 **프로덕션 빌드**로 (dev 모드는 webpack·소스맵이 상주하고 실행 중에도 재컴파일한다):

```bash
npm run build
pm2 start ecosystem.config.js && pm2 save && pm2 startup
crontab -e   # * * * * * curl -sf localhost:3100/api/health >/dev/null   ← 무장 + 복구
```

키는 앱의 **⚙ 설정**에서 넣을 수도 있다 — 저장 시 `data/secrets.json`(0600)에 쓰고 즉시 반영된다(재시작 불필요). 실전화 절차·체크리스트는 `RUNBOOK.md`.

## 남은 것 (실전화 전 필수)

1. **토큰 컨트랙트 온체인 검증** — 전송 경로가 지갑 보유분에서 심볼로만 고른다(클론 토큰 위험). 검증 후 fail-closed 필요
2. **실키 소액 검증** — bybit/OKX/빗썸 체결량 조회(서명·필드는 배선했으나 실응답 미확인). 이게 안 되면 그 거래소들에 일손실 한도가 작동하지 않는다
3. **DRY_RUN 전체 리허설 1회** — 새 `recv` 단계와 입금 폴링 실동작 확인
4. 업비트↔바이낸스 네트워크 코드 매핑(읽기 전용 키로 `/v1/status/wallet` 덤프)
5. funding-basis 실행 배선(HL/Lighter), SPL/TRC20 전송 배선(현재 EVM만)
6. 소액 실거래 후 `DRY_RUN=false` 전환
